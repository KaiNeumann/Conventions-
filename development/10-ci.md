# CI and Releases

Pattern proven in fotozahlungen (Woodpecker) and RAT (canonical
packager). Applies when a project has builds worth automating — skip
ceremony for pure documentation repos.

## Pipeline (pattern)

1. CI validates the build (Docker build without publishing, lint, tests)
   on every push.
2. Release pipeline: version bump in code → tagged commit → canonical
   packager run ([`08-packaging-desktop.md`](08-packaging-desktop.md)) →
   artifacts attached to the release.
3. Images/binaries produced by the release pipeline follow the tagging
   rules in [`07-packaging-web.md`](07-packaging-web.md).
